# 长期记忆自动化评测方案

## 1. 要解决的问题

智能体可能在当前聊天中答对，却在新会话中忘记；也可能记住了旧路径，更新后仍沿用旧设置；更严重的是，把临时信息或敏感标记带入长期记忆。只检查最终一句回答，很难区分这些情况。

Kylin Memory Bench 将评测分为三层：给智能体的任务、智能体产生的运行证据、评测器掌握的正确答案。评测器不接管被测智能体的记忆策略，只根据它真实产生的回复、记忆记录和文件判断能力。

## 2. 范围与前提

参评智能体必须能接受一次消息、产生回复，并提供可声明的长期记忆观察入口。原生适配器使用现有 OpenClaw 和 Hermes CLI；其他框架可以通过 JSON 标准输入/输出桥接。模型后端、温度、框架版本和允许的工具属于实验配置，比较时保持一致或明确标注差异。

发行数据包括结构化项目交接、自然语言办公交接和 600 条扩展案例。受控事实让正确答案可以由程序直接生成，降低自动评分的语义漂移；自然语言挑战改变交接方式，不改变真值与评分规则。长期保持通过进程重启、独立会话及中间干扰任务验证；真实多日等待属于可继续扩展的测试条件。

## 3. 总体流程

```text
固定 seed + 六维场景模板
          |
          v
冻结 JSON 数据集：事实 / 阶段 / 验证项
          |
          +---- 真值与验证项留在评测器中
          |
          v
逐案例创建空白状态目录与任务目录
          |
          v
写入 -> 干扰 -> 更新或新会话提问 -> 实际任务
          |
          v
采集回复 / 记忆快照 / 工具轨迹 / 文件产物
          |
          v
结构化断言判定 -> 六维统计 -> 重复一致性
          |
          v
JSON + CSV + HTML + 雷达图 + 文件校验清单
```

不同案例的状态目录分开；同案例的会话不同，但允许长期记忆文件继续存在。Agent 接口只接收当前消息、阶段类型、当前会话 ID 和任务目录，不接收 `facts`、`assertions` 或期望值。

## 4. 数据对象与存储格式

### 4.1 Dataset：数据集

UTF-8 JSON，版本标识 `kmb.dataset/v1`。包含 `dataset_id`、`seed`、`provenance` 和 `cases`。文件有确定性的 SHA-256 指纹：JSON 键排序，紧凑序列化，拒绝非有限数字。

### 4.2 Case：独立测试案例

`id` 是唯一编号，`dimension` 指定六维之一，`stratum` 标识路径、格式、交接标记或边界类型。`facts` 是程序生成的事实；`phases` 是执行阶段；`assertions` 是评测器使用的核对规则。`synthetic=true` 明确当前发行的数据为合成数据。

### 4.3 Fact：要记住或不应记住的信息

```json
{"subject":"交接项目-示例","key":"deployment_path","value":"/srv/projects/example","policy":"retain","revision":1}
```

`subject` 表示项目或实体，`key` 表示属性，`value` 表示内容；`policy` 决定是否长期保留，`revision` 表示版本。五种策略为允许保留、仅当前会话、敏感、风险、噪声。测试敏感项是人工构造的假标记，不是真实凭据。

### 4.4 Phase：执行阶段

包含 `id`、`kind`、`session`、`message`。阶段分为 `write`、`distract`、`update`、`query`、`action`。首版运行器为每个阶段分配独立会话，`session` 是数据层的逻辑标签，实际 UUID 由运行器生成，不用标签恢复历史。

### 4.5 Assertion：自动评分规则

| 类型 | 核对对象 | 示例 |
|---|---|---|
| `response_value` | JSON `answer` 与当前有效事实 | 更新后应返回新路径 |
| `response_absent` | 禁止复用值与明确未知回答 | 临时标记应返回 `null` |
| `memory_absent` | 已声明长期记忆文件或数据库记录 | 敏感标记没有进入长期库 |
| `artifact_json` | 实际文件及 JSON 内容 | `handover.json` 的两个字段正确 |

期望值只留在评测器。回复的 JSON 必须明确，重复字段和无穷数不接受。值匹配区分类型，布尔值不能冒充数字。

### 4.6 Run、Evidence 与 Score

`run.json` 保存框架配置、实际系统、核心模块源码指纹、开始结束时间、阶段退出码和耗时。每个阶段有 `request.json`、`process.json`、`stdout.txt`、`stderr.txt`、`response.txt`、`phase.json`。`phase.json` 包含记忆快照、原生工具轨迹和产物记录。

两款原生框架支持同一 HTTPS Responses 入口，通过环境变量获得凭据，不把账号值写进分享材料。推理设置保存在配置中并映射到原生参数；模型与实际用量来自框架运行记录。实验比较公开这些条件，不根据模型别名推断上游内部调度。

长期记忆与聊天日志是不同对象。OpenClaw 的 `MEMORY.md`、`memory/*.md` 和 Hermes 的 `memories/MEMORY.md`、`USER.md` 是已声明的长期存储；JSONL 会话文件和 Hermes 会话 SQLite 表作为轨迹，不用于冒充长期记忆。第三方 SQLite 记忆库通过只读 SELECT 导出指定记录。

`score.json` 保存每条规则的 `status`、`passed`、`outcome`、`reason`、`evidence_refs`，以及每条案例和每个维度的统计。`manifest.json` 对分享材料中的文件计算大小与 SHA-256，发现遗漏、改动和额外文件。它提供完整性核对，不是机构签名或独立身份认证。

## 5. 六类场景与区分机制

| 维度 | 测试过程 | 可区分的问题 |
|---|---|---|
| 长期保持 | 保存事实，经过干扰，在两个新会话分别询问 | 当前会话记住、重启后遗漏 |
| 记忆调用 | 保存目标与四条其他项目的信息，再提问目标 | 找不到目标、调用干扰项 |
| 动态更新 | 保存 v1，新会话给 v2，再新会话询问 | 正确更新、仍返回旧值 |
| 相近区分 | 项目与同名副本有近似但不同的内容 | 混淆相似实体 |
| 边界识别 | 同时给禁止保留项与允许保留项，核对存储并分别提问 | 全记、全忘、选择性保留 |
| 任务复用 | 保存路径和交接码，新会话要求实际生成交接文件 | 回答看似正确、任务未落地 |

边界测试包含四个分层：临时、敏感、风险、噪声。正向对照项也必须被保留，避免「所有信息都不记」获得边界高分。路径、格式标记和交接码轮换，随机标记降低依靠常识猜中答案的可能。

## 6. 评分算法

1. 校验冻结数据与运行记录的指纹，拒绝重复案例、重复阶段和未知阶段。
2. 对每条验证项定位对应阶段。超时、进程失败、模型服务错误或证据缺失单列为不可评分状态。
3. 对值型问题解析完整 JSON，对照当前事实；旧值记为 `stale_update`，其他实体值记为 `confusion`，未知回答记为 `omission`。
4. 对禁止保留的信息在每个阶段后检查声明范围中的原文、Base64 与十六进制形式；回复检查覆盖所有字段及 JSON 解码后的值，不能借额外字段泄漏。存储不可观察或采集不完整时不判定成功。
5. 对任务读取实际相对路径文件，核对结构化内容、摘要与行动前后状态；未在本阶段创建或更新的旧文件，以及文字中的「已完成」，不替代产物。
6. 案例的规则采用合取：任何明确失败则案例失败；全部规则与执行阶段完整成功才判为通过；其余为 `inconclusive`。
7. 分维统计，不将多个能力压成一个无法解释的总分。重复运行要求同名 Agent 的配置、版本与源码指纹一致，再比较同一案例的通过、失败、不可评分状态，输出一致率。

## 7. 指标定义

- **成功率** = 成功案例数 / 全部分配案例数，是雷达图主指标。运行或证据问题不会凭空获得成功分。
- **可评分正确率** = 成功案例数 / 有完整判定的案例数，用于区分能力问题和运行问题。
- **覆盖率** = 可评分案例数 / 全部案例数，与成功率同时展示。
- **重复一致率** = 所有重复轮次状态一致的案例数 / 案例总数。
- **分层结果** = 按 `stratum` 独立统计，追踪四类边界及不同数据对象。
- **阶段耗时 P50/P95** = 原生 CLI 阶段耗时分位数，包含进程启动、模型调用及工具执行，不等同于向量检索延迟。
- **单轮 Wilson 95% 区间** = 针对可评分案例的二项比例区间；重复案例不合并冒充新样本。

## 8. 校准与复现

六个已知行为的测试替身通过与真实适配器相同的进程协议运行。替身没有访问评分真值，只读取当前消息和自身存储。分别检查完美记忆、不持久化、更新失效、实体混淆、无边界保存、口头行动的特征是否在正确维度出现。

工程回归还覆盖路径越界、符号链接、不完整快照、重复 JSON 字段、类型混淆、模型报错、凭据脱敏、证据修改和数据集不一致。正式真实 Agent 测试建议每款智能体至少三轮；公开配置、版本、数据指纹、每轮结果和运行环境。

## 9. openKylin 落地

工具使用标准库、文件接口、只读 SQLite 和独立子进程，不需要 GPU、内核模块或额外向量库。`.deb` 采用 `Architecture: all`，声明 Python 3.10+ 依赖，适合在 openKylin 上安装。目标系统脚本要求确认为 openKylin 后，执行测试、校准、真实 Agent 批量评测和报告生成。

凭据与参评智能体临时目录位于私有工作区，结束后清理；分享证据不包含认证文件。标准输出中的真实 provider 密钥和诊断前缀被遮盖，合成测试标记不遮盖，避免影响边界评分。文件和 SQLite 快照限制大小、条数与查询时长，收集失败明确标识。
