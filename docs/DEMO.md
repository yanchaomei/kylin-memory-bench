# 3—5 分钟真实桌面演示

2026-10-16 已完成真实 openKylin 2.0 SP2 UKUI 录屏，制作约 3 分 50 秒的中文旁白与字幕版。视频包含系统/原生版本检查、冻结数据、双框架实际执行监视、修订前后任务文件、六维雷达与失败案例、独立 Ubuntu 三轮研究，以及证据核验与导出。实际运行等待作加速剪辑，并在相应章节明确标注。成片、字幕与完整材料见 [公开发布页](https://github.com/yanchaomei/kylin-memory-bench/releases/tag/v0.2.0-oscc)。下文保留可供复录的操作流程。

## 录制前

在 openKylin 桌面完成两个真实智能体的模型连通性测试与一次完整运行。冻结数据、框架版本和配置，保留独立 run 目录。隐藏账号信息、认证文件和终端历史中的凭据。不用校准替身冒充真实智能体。

## 建议流程

| 时间 | 画面与操作 | 讲解重点 |
|---|---|---|
| 0:00—0:30 | openKylin 桌面与 `kmb doctor --require-openkylin` | 这是运行环境，不是其他系统播放录像 |
| 0:30—1:10 | 展示一条交接案例：项目、路径、交接码与保留策略 | 同时有应记住与不应记住的信息 |
| 1:10—2:10 | 展示两款真实 Agent 的阶段执行录屏，较长等待可剪辑并标出 | 写入、新会话、更新与行动是连续过程 |
| 2:10—2:50 | 展开实际记忆文件、更新后回复、`handover.json` | 核对真实证据，不只相信完成声明 |
| 2:50—3:40 | 打开真实 Agent 六维雷达图和指标表 | 两款智能体分别在哪些方面表现不同 |
| 3:40—4:30 | 展开失败案例原因、证据引用，执行 `kmb verify` | 自动评分可解释、材料可复算 |

每款智能体完整 24 条数据需要 88 次阶段调用；已完成历史运行的阶段累计时间约 14—19 分钟，墙钟时间还包含证据采集。两款串行运行应预留约 40 分钟，并留出网络抖动余量；不用假定整个实验能在 3—5 分钟内现场跑完。

录制前先完成完整评测，再在真实 openKylin 桌面录下一个关键案例的执行及报告核查。每维 1 条的演示集适合展示流程，长等待可剪辑或加速并明确标示；末尾展示已完成的完整报告。两个数据指纹分别标注，不把演示集与完整评测混成同一结果。

## 录制命令

```bash
python3 kmb generate --seed 20261003 --per-dimension 1 --out results/demo-data.json
python3 kmb run --dataset results/demo-data.json --config configs/real-api.json --out results/demo-real
python3 kmb compare results/demo-real/*/repeat-001 --out results/demo-report
python3 kmb verify results/demo-real/OpenClaw-API/repeat-001
```

文件动作通常最容易讲清楚：先告诉智能体某项目的部署路径和交接码，再开新会话让它生成交接文件。最后核对文件中的两个字段。更新案例展示原值被更正后的实际回答；边界案例展示禁止信息不保留，同时允许信息仍能找回。

录屏文件必须来自真实 openKylin 桌面中的真实执行。交付前核对时长、声音、文字可读性，以及两款真实 Agent 和多维对比雷达是否都出现。
