# 自然语言办公交接挑战集

`data/dialogue-24.json` 是 **程序化合成** 的 24 条办公交接案例，六个维度各 4 条。它将原先直接展示 `facts` JSON 的输入改为自然语言消息，用于检查智能体能否从对话中提取、保存并正确使用交接资料。数据以合成事实提供确定真值，2026-10-04 已完成 OpenClaw 与 Hermes 的真实 API 单轮评测。

## 场景覆盖

| 维度 | 场景 |
|---|---|
| 长期保持 | 正式移交一个项目的设置，经过临时办公任务打断，在两个新会话中分别核对 |
| 记忆调用 | 一次移交 5 个不同项目的信息，新会话中只查询其中一个项目 |
| 动态更新 | 上午交接旧设置，下午正式修订，再查询当前有效设置 |
| 相近区分 | 前 2 条使用清楚不同的项目名，后 2 条使用同类项目的不同组别，分别核对两者 |
| 边界识别 | 本次会话临时信息、虚构敏感资料、未经核实的来函、闲聊噪声各 1 条；每条都有另一项目的合法保留对照 |
| 任务复用 | 新会话从已保存资料取出部署目录和交接编号，实际创建 `handover.json` |

大部分交接资料是中文，2 条案例使用英文登记句子、中文查询。项目名按办公事项重命名，不包含真实机构或用户资料。路径、格式标识和交接编号仍是源生成器给出的精确字符串；其中不透明标记保留精确评分用途，并非对真实业务数据分布的模拟。

## 真值与评分

脚本调用既有 `generate(seed, 4)`，复用 `kmb.dataset/v1`。除了实体 `subject` 重命名外，所有事实的 `key`、`value`、`policy`、`revision` 和全部 `assertions` 原样保留；阶段的 ID、类型、会话及顺序也不变。同一实体的字段、修订和消息采用一致名称。数据集使用独立 ID `kmb-dialogue-<seed>-4`，来源记录包含原数据集 ID，并保留 `programmatic_synthetic`、`human_gold: false` 和逐案例 `synthetic: true`。

每个待评分值都在交接或正式修订消息中明确出现，不需要计算、猜测或外部知识。当前查询、行动和打断消息均不包含事实值。消息移除了 `MEMORY_INPUT`、`MEMORY_QUERY`、`MEMORY_ACTION` 标签和事实 JSON，但保留 JSON 回复协议，便于使用原评分器精确核对 `answer`。

边界案例在交接时说明不应保留的理由，同时要求保存另一项目的正式资料。评分继续要求禁止值不进入已声明的长期记忆观察范围、不在未来回复中泄漏，且新会话明确返回未知；合法对照必须返回正确值。存储不可观察或采集不完整仍是不确定，不是通过。复用维度要求本阶段新建或更新的实际 JSON 文件内容与真值一致，口头完成声明不计成功。以上都是既有断言，不改变评分语义。

## 生成与验证

在 `benchmarks/kylin-memory-bench` 目录运行，仅需 Python 标准库：

```bash
python3 -B scripts/generate_dialogue_challenge.py
python3 -B -m unittest discover -s tests -p test_dialogue_challenge.py -v
python3 -B kmb validate data/dialogue-24.json
shasum -a 256 data/dialogue-24.json
```

默认 seed 为固定值 `20261003`，默认输出路径相对脚本所在项目定位为 `data/dialogue-24.json`，不依赖调用时的工作目录。相同 seed 的生成内容与序列化字节确定一致；默认生成会覆盖这份新挑战集，不修改旧样例。要保留另一 seed 的版本，可显式指定新文件路径：

```bash
python3 -B scripts/generate_dialogue_challenge.py --seed 7 --out /tmp/kmb-dialogue-7.json
```

脚本和 `kmb validate` 输出的 `sha256` 是现有 `model.digest` 对规范化数据计算的数据指纹，与评测运行的 `dataset_sha256` 一致；`shasum` 输出的是带缩进 JSON 文件的原始字节指纹，两者用途不同。

## 适用范围与限制

这份数据可直接交给支持自然语言消息的真实智能体适配器，使用原运行器、阶段隔离和自动评分。应为它创建新的运行证据目录；不能与旧结构化数据集混合汇总或把旧结果迁移过来。现有校准 fixture 依赖 `MEMORY_*` 标签，不能解析这份对话，不能作为该挑战集的通过基线。

数据生成器与单元测试本身离线运行，不调用真实模型。构造回复和文件观察用于验证评分契约；智能体能力结果来自另行保存的真实运行证据。

两款框架各完成 24 条案例、88 个阶段、52 个断言，六维全部通过，两个 run 均通过完整性校验。运行环境为 Darwin arm64，报告为 `results/dialogue-https-report-20261004/`，具体配置、耗时与证据核查见 `TEST_REPORT.md`。该报告与相近项目名称的结构化三轮测试分别展示，不混合汇总。

24 条模板化案例用于办公交接回归，当前边界策略在消息中明确告知，测试的是正确执行保留与拒答指令。长时间真实办公、含糊表达、自主识别敏感内容等应作为新增测试条件，由新案例和独立报告验证。
