## 2. 必须保持的控制条件

- 同一配对两臂使用相同查询、动作、阶段数量与执行顺序，只替换相关资料；输入差异由注册生成器重新核对。
- 每条案例使用空白 profile，每阶段独立会话；同案例保留文件和声明的长期存储。会话日志、记忆存储、任务产物分别归档。
- 两款框架使用同一 HTTPS Responses 入口和请求模型，记录原生版本、推理设置、用量和源码指纹。不同框架的原生提示、工具实现和存储策略属于系统配置，不将整体差异归因某个单独算法。
- 不完整观察、进程错误、协议错误与明确错误分别统计；完整配对比例与目标达成差值同时公开。
- 先固定生成器、目标规则与主要评价端点，再运行真实 Agent；不根据模型回答改写 expected 或删除失败案例。

## 3. 校准与消融矩阵

已知行为对照不参与真实智能体排名，用来检验评分器能否正确识别退化。每个对照独立运行三轮。

| 对照 | 变化因素 | 预期可识别现象 |
|---|---|---|
| perfect | 正确保留、按 revision 更新、按实际事实行动 | 两臂按政策正确；仅提供臂达成记忆依赖目标 |
| session-only | 不持久化任何记录 | 提供资料也无法跨会话完成目标，收益为 0 |
| stale | 同一字段保留首次版本 | v3 查询及反馈后的第二次文件行动失败 |
| confuse | 查询使用其他实体的值 | 主任务或无资料拒答失败；文件行动另行核对 |
| unsafe | 禁止项也持久化 | 允许信息仍有用，但边界存储检查失败 |
| claim-only | 能保存和回答，但不创建文件 | 回答维度正常，真实行动与目标端点失败 |

资料收益与安全结果不能互相替代：unsafe 对照可能有高收益却不安全，恒定拒答可能安全却没有任务收益。这正是把二者分开的原因。

另在 64 次干扰的 12-case 先导世界运行 perfect 对照，共 808 个阶段，检验长序列、持久化、记录大小与证据关联是否可运行；它是工程压力校准，不是大模型长期记忆成绩。

## 4. 真实框架先导

被测系统为 OpenClaw 2026.3.8 (3caab92) 与 Hermes Agent v0.8.0 (2026.4.8)，请求模型 `gpt-6-sol`，显式客户端推理设置 off。两端使用同一冻结 12-case 数据，各 1 轮。机器环境和实际配置以原始 run 为准。

主要读取六维按政策成功率、主目标达成、配对资料收益、完整配对覆盖、无资料安全行为；逐例查看模型原文、记忆快照、工具轨迹和两次实际文件。先导单轮用于暴露问题与确认完整流程，不与原先结构化三轮或自然语言样例混合成一个成功率。

阶段耗时包含 CLI 启动、远端模型和工具执行；两款客户端并行运行，另有本地工程校准，因此本轮耗时只作运行诊断，不作为算法加速或独占性能对比。

## 5. 冻结测试扩展

先在标准 48-case、4 次干扰条件下每款三轮，按相同配对跨轮汇总；再分开运行 1/16/64 次干扰，绘制保留和任务目标随压力变化的曲线。每个图点保留完整分母、区间、异常及原始记录；不同压力数据不直接混合为新的独立案例。

若要研究记忆后端贡献，再设计相同输入历史的后端替换实验，并排除聊天、任务文件与缓存旁路。本版资料扣除实验不能自动等同于后端关闭消融。若加入开放式偏好或流程总结，另设语义评分、独立裁判与人工校准协议，不把精确字符串评分扩大解释为任意语言理解评分。
