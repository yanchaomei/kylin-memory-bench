# 增量任务与配对资料收益协议

版本：Kylin Memory Bench 0.2.0；协议：`kmb.episodes/v1`。核对日期：2026-10-09。

## 为什么增加这套协议

原有六维样例检验保存、调用、更新、区分、边界与行动，是评分器和原生框架的基础验收。新的自然语言样例在两款框架上均通过，说明需要继续增加干扰和过程依赖，而不是只扩充同样的简单问题。

新协议借鉴 MemoryAgentBench 的分阶段信息输入、MemoryArena 的跨会话行动依赖，以及 OSWorld、tau-bench 的实际产物/终态评分。具体机制与论文身份核验见 [顶会方法调研](TOPCONF_METHODS_20261009.md)。本项目独立生成办公数据，不使用上游排行榜的题目或数字；配对差值和统计方案是本项目的实验设计，不声称每篇参考论文都采用同一种方法。

## 一条任务怎样执行

每条 episode（有连续关系的一组任务阶段）使用独立工作区。每个阶段仍开新进程与原生会话，只有该工作区的长期记录和实际任务文件保留。

| 维度 | 新增过程 |
|---|---|
| 长期保持 | 保存目标后经历多次无关资料写入，在两个新会话分别查询 |
| 记忆调用 | 多实体事实与后续干扰共存，查询中不附带答案 |
| 动态更新 | v1、v2、v3 依次出现，再投递迟到 v1，最终应使用 v3 |
| 相近区分 | 相近实体名配独立随机值；另一实体的值不含目标值，不能通过删除后缀猜中 |
| 边界识别 | 临时、敏感、风险、噪声分层；每个阶段观察禁止项，并保留合法信息对照 |
| 任务复用 | 实际生成 `checkpoint.json`，经过干扰和固定版本反馈，新会话生成更新后的 `handover.json`；分别核对两份文件 |

任务反馈是预先冻结的版本事实，不根据运行回复临时编造。它测的是执行给定反馈后的跨会话任务复用，不是完整的自主 GUI 环境模拟。已有产物作为该任务的持久信息可继续访问；这与只检查一次最终答复不同。

## 配对干预是什么

同一任务生成两个实验臂，使用独立的空白工作区：

- **provided：提供相关资料。** Agent 通过自己的工具和记忆机制保存资料，后续完成指定回答或文件任务。
- **withheld：扣除相关资料。** 把目标实体的各版本记录替换为无关实体的等条数记录；保留其他资料、干扰、阶段顺序及全部查询/行动文字。

最终查询和行动在两臂逐字一致，阶段数量一致，目标真值只留在评测数据的 `intervention.objective`。`adapter_request` 不转发干预元数据、事实表或评分规则。案例 ID 不包含实验臂名称；两臂执行先后按 seed 固定交错。

本协议是注册生成器的冻结任务，不接受任意改写后的配对声明。导入时按 seed、split、每维任务数和干扰数重新生成，并逐字核对整个规范化数据。改动无关输入、复制任务换 ID、修改目标真值或把拒答改成成功，都被拒绝。原有 `kmb.dataset/v1` 普通任务仍可扩展；外部自由编写的配对协议需要单独定义可审计干预规则，不冒用本协议标签。

这是**相关资料可用性对照**，不叫「关闭记忆后端」。它改变目标资料是否曾被提供，测量该资料对后续目标达成的作用；不能据此归因某一种索引、记忆表示或提取算法。若后续要比较不同记忆后端，应另设相同输入历史、不同后端的实验，检查聊天、产物和缓存中的旁路信息。

## 两种分数必须分开

1. **按政策正确执行任务。** 有资料时应答对/生成正确文件，无资料时应明确未知/不生成无依据文件。该分数继续进入六维报告。
2. **同一个任务目标是否达成。** 两臂都按同一正向真值核对。无资料时正确拒答属于安全行为，但没有完成目标，不能当成无记忆任务成功。

每条评分记录新增 `intervention` 和 `target_attainment`。目标达成同样使用完整 JSON 或实际文件内容，不调用另一模型打分；运行阶段未完成时记不可评分。

`artifact_absent` 核对不应产生的文件。只有指定路径进入实际 `artifact_scope`、观察未报错且没有文件，才判通过。缺失观察范围或读取失败为不可评分；存在垃圾内容的文件仍为失败。当前行动是否新建/更新文件继续由行动前后摘要和文件状态判断。

## 配对统计

单轮同一配对的资料收益为：

```text
gain(pair, run) = target_success(provided) - target_success(withheld)
```

差值取 -1、0、1，报告用百分点（pp）表达。重复运行先在同一 `pair_id` 内平均，再对独立配对求均值。Bootstrap 固定 seed，在任务配对层重采样，默认 2,000 次；不把多个阶段、问题或重复轮次当作新增独立样本。完整配对少于 2 个时不输出区间。

任一重复轮次缺少可判定的实验臂，该配对不进入收益点估计，必须同时公布完整配对覆盖率、全部分配任务的六维结果和逐例异常原因。报告另列 provided 目标达成率、withheld 目标达成率及 withheld 安全行为率。未知资料却命中精确目标值是需要核查的诊断信号，不自动认定为已证明的数据泄漏。

## 数据划分与规模

development 与 test 采用不同确定性事实世界，实体/值不交叉。两者使用同一类模板，因此叫**事实世界留出**，不叫未见任务模板泛化。数据均为程序化合成，`human_gold=false`，固定 seed、配置和代码版本可以重新生成。

| 文件 | 配对数 | 案例数 | 阶段数 | 用途 |
|---|---:|---:|---:|---|
| `episodes-pilot-12.json` | 6 | 12 | 88 | 短运行与真实框架先导验证 |
| `episodes-development-48.json` | 24 | 48 | 352 | 开发与消融，不与 test 合并 |
| `episodes-test-48.json` | 24 | 48 | 352 | 冻结测试，覆盖四种边界策略 |

干扰会话数支持 1–64，可生成多个独立报告比较压力变化。已生成的数据量与已完成的真实运行量分开记录，实际成绩以本轮报告和原始证据为准。

## 一键复现

```bash
python3 kmb generate-episodes --seed 20261009 --split test --per-dimension 4 --interference-sessions 4 --out results/episodes.json
python3 kmb validate results/episodes.json
python3 kmb run --dataset results/episodes.json --config configs/real-api.json --repeat 3 --out results/episode-agents
python3 kmb compare results/episode-agents/*/repeat-* --out results/episode-report
```

输出沿用 JSON、CSV、HTML 与六维雷达，并增加 `paired_metrics.csv` 和配对统计章节。JSON Schema 描述局部字段，Python 契约进一步校验成对完整性、相同目标和相同查询；不能只用 JSON Schema 代替后者。历史数据和记录保持原文件与摘要，不改写为新协议结果。
