# 相关工作与方案定位

核对日期：2026-10-04。以下来自作者项目页与官方代码仓库。本项目独立生成办公交接数据，不复制这些数据集，也不把本项目得分与其排行榜横向比较。

## 已有评测提供了什么

| 工作 | 主要评测对象 | 对本项目的启发 |
|---|---|---|
| [LoCoMo](https://github.com/snap-research/locomo) | 长期对话，包含问答与事件总结等任务 | 不能只检查最近一段聊天，应安排跨会话的信息保持 |
| [LongMemEval](https://github.com/xiaowu0162/LongMemEval) | 信息提取、多会话推理、知识更新、时间推理和拒答；提供按时间组织的历史与证据标注 | 更新与拒答必须成为独立维度，保留来源与证据位置 |
| [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench) | 分块增量交互，覆盖检索、测试时学习、长程理解和冲突解决；不同任务采用精确匹配或模型评分 | 数据分阶段输入，评分规则随任务对象选择，而不是只报一个总分 |
| [LongMemEval-V2](https://xiaowu0162.github.io/longmemeval-v2/) | 从网页智能体历史轨迹中提取可复用经验，经 Insert、Query 和固定 Reader 验证回答与查询耗时 | 记忆评测需要关注行动经验，轨迹和记忆检索链路可以成为显式对象 |

已有研究已经覆盖更新、拒答、增量交互和行动经验。Kylin Memory Bench 不将这些能力名称本身作为首创；重点是把赛题要求落到 openKylin 社区可运行、可审查的工程流程。

## 本项目的具体取舍

1. **以原生框架为被测对象。** 同一个 CLI 可以调用 OpenClaw、Hermes 或第三方标准输入/输出适配器，不要求它们采用指定的记忆算法。新会话与长期存储分开，避免把聊天历史当作长期记忆成绩。
2. **以多种实际产物共同评分。** 回复、记忆文件/数据库、工具轨迹和任务文件放在同一阶段记录中。边界案例核对禁止项与合法对照；任务复用核对实际文件与当前行动的新旧状态。
3. **用受控真值减少评分漂移。** 路径、格式标记、版本和交接码均由固定 seed 生成。核心评分是可重算的结构化规则，不额外调用裁判模型；对开放式语义问题则应新增明确的评分协议，不能直接沿用精确字符串规则。
4. **面向社区复现。** 标准库运行、只读 SQLite、独立子进程、离线报告和 `.deb` 包；每轮保存数据、配置、版本、源码和文件指纹，便于升级框架后重新评测。

## 结果应如何阅读

六种已知行为对照用于确认评分器是否正确；两款真实 Agent 用于确认实际记忆流程是否能被自动观测，并展示能力差异。自然语言挑战集增加对话表达，但正确值和边界策略仍然明确，可逐条解释。600 条扩展数据用于增加独立案例规模，已生成的数据量与已完成的运行量分别报告。

本项目的当前证据回答的是「这组冻结任务在该框架、模型与环境上如何执行」，不是通用智能体能力排名。正式 openKylin 桌面记录与其他平台工程结果分别归档，使评审可以复现同一条流程。
