# 项目故事与演示主线

## 一句话

**智能体说「我记住了」不算数：让回复、长期记录和实际行动一起作证。**

## 1. 冲突：一句答对，可能掩盖三种错误

办公助手能在当前聊天中复述项目目录，不代表换个会话还记得；保存了新目录，不代表下一次不会沿用旧值；生成「已完成」的文字，也不代表交接文件真的存在。把这些结果都交给另一个模型打分，还会引入评分模型自身的理解偏差。

## 2. 洞察：记忆能力应按过程评测

长期记忆既是回答能力，也是选择、更新和行动能力。评测需要安排写入、干扰、新会话、更新与任务执行，并把每一步产生的证据保留下来。应保留的信息与禁止保留的信息必须同时出现，否则「全部不记」也可能看似安全。

## 3. 方案：统一证据，六维自动核对

Kylin Memory Bench 不替被测智能体管理记忆。它用适配器调用不同框架，给每条案例建立空白状态空间，逐阶段启动独立会话；再收集回复、长期存储快照、原生工具轨迹和实际任务产物。事实与核对规则留在评测器中，当前消息不会附带完整真值表。

受控数据中的正确值可由程序直接生成，所以核心评分不需要调用另一个大模型。六个维度分别呈现长期保持、调用、更新、相近区分、边界识别与任务复用；每条失败有实际值、原因和证据位置。

## 4. 证据：既能识别对照，也能发现真实问题

六种已知行为对照验证评分器能分别识别不持久化、拒绝更新、实体混淆、无边界保存和口头行动。两款真实框架的三轮评测发现，OpenClaw 有一次跨会话保持遗漏；两端都能保存合法信息，却在未知项目上误用相近项目值。后者是本工具能揭示、普通问答检查容易遗漏的记忆边界问题。

后续自然语言办公挑战集使用另一份冻结数据，加入中文交接与英文登记的中文查询。不同数据、配置和平台分别报告，不把它们混成一张高分表。

## 5. 愿景：成为社区可持续运行的检查工具

工具只依赖 Python 标准库，提供 CLI、离线报告和 Debian 包。社区可以新增框架配置、补充案例，再用同一套证据协议批量比较；每次修复记忆机制后都能复跑并追踪变化。

## 演示时要让评委看见的三个对象

1. **新会话里的实际回答**：旧聊天已不在输入里，回答来自保留下来的记忆。
2. **按阶段保存的长期记录**：更新与边界是否执行，可直接检查存储快照。
3. **当前行动生成的文件**：真实产物、内容和新旧状态一起验证，完成声明不能代替结果。
